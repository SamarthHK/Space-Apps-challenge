# Implementation status

## Multicrop outcome pilot (2026-11-15)

The first real training pipeline now exists: fresh Broadbalk wheat/beans/oats/
forage-maize/potato and Woburn wheat sources, plus site-matched NASA POWER history
for 1981-2022. Source-normalized records and versioned datasets persist in
PostgreSQL through migration 007; immutable originals and source notes remain.

The expanded corpus contains 12,580 source rows and 30,680 weather-day rows at
two English experiment sites. The retrospective feature assembler admits 8,964
candidates, uses a day-before-sowing cutoff, and preserves explicit exclusions.
Four crop-specific models were trained with distinct main-plot groups and later
seasons held out. Field beans lack enough usable training rows after splitting.
Models are compared with a baseline and a no-weather ablation; improvements are
mixed, not evidence of a generally reliable crop-selection engine.

Commands: `acquire-outcomes`, `build-outcomes`, `train-outcomes`, `predict-outcome`.
The last accepts prepared features, not arbitrary-field recommendations.
Artifacts: `data\exports\multicrop-dataset-v3` and
`data\exports\multicrop-model-v3`. See README for full commands and limitations.
`operational_recommendation_ready` remains false. This explicitly retrospective
path does not alter scientific approval statuses or bypass the original
`prepare-ml` loader.

**Full inventory incomplete.** The current `Plan.md` override removes scientific
approval as a software-health requirement. `health-check` now executes live
acquisition, imports, canonical deduplication and export-integrity checks for
the implemented PDOK/NASA/Woburn paths. Its pass/fail report is separate from
the original S01-S11 scientific acceptance ledger and from training readiness.
Earlier prototype completion claims do not apply to the full inventory.

The replacement implements exact plan inventory extraction, typed observations,
fail-closed coverage reports, fresh official parcel/NASA acquisition, immutable
raw evidence, shared versioned PostgreSQL/PostGIS persistence and preparatory
independent readback/export checks. `uv.lock` records resolved dependencies.

Independent geographic preparation now includes reusable KML/KMZ parsing,
metadata and original-geometry retention, stable identity, explicit topology
repair, metric projections, versioned boundary persistence and geographic
exports. The authentic reference parcel passes; broader geometry and spatial
product cases remain unverified and S03 remains blocked.

Actual reference evidence is a 2025 RVO/PDOK winter-wheat parcel in the
Netherlands and NASA POWER daily data queried at its representative point.
This is an infrastructure reference, not a Karnataka crop/cultivar trial.
Seven parameters produce 2,555 pending records per acquired response snapshot.
Pending data are excluded from accepted observations. Repeat imports of the
same asset do not duplicate records; distinct raw snapshots remain separate.

The old modules, synthetic/fallback tests and baseline crop configuration have
been removed. Their committed baseline remains in Git and an ignored local
archive. Existing user datasets and the earlier Git stash were not removed.

Full atomic definitions, scientific references/tolerances, complete source
bindings, regional crop/cultivar/trial/management evidence, authentic laboratory
and all 14 instrument-category records remain outstanding. Domain migrations,
domain implementations and complete acceptance suites are not complete.

ML-data remediation adds reviewed field aliases, a separate canonical observation
layer, acquisition-to-observation links and completed/failed NASA job states.
Repeated genuine response snapshots retain separate source evidence but resolve
to 2,555 canonical observations and one canonical reference field when the
provider content is unchanged. Current acquisition counts are emitted in each
health report rather than maintained as a second, stale data inventory.

The published Woburn Ley-arable trial has been acquired and imported: 2,240
plot-year records, including 12 missing yields, with original factor tables,
management notes and workbook-derived units. Source plot-code collisions are
flagged, not merged. These are pending empirical candidates from one UK site.
Dataset citation, attribution and acknowledgement are retained in exports and README.

`prepare-ml` exports reproducible candidate/feature/target/split/lineage tables
and explicitly blocks training. Decision timestamps, reviewed preceding sequences,
matched environmental data and scientific validation remain unresolved in that
original preparation path. The new retrospective models above are separate;
neither path completes the full Plan.md inventory or an operational rotation engine.

See `README.md` for executable commands, preparation limits and database setup.
